# 人工覆核同錯誤回溯

> 人工標註介面統一由 `jyut-ocr-bench` 維護。先讀 `manual-review-tool.md`，經技能嘅 `scripts/review.py` 開啟共用畫布；呢份筆記只描述資料、工作流程同採納規則，唔要求另建 HTML／server。同步快照、人工標註同採納答案係三個獨立步驟。

用於已有人工修訂、要交疑字畀人判斷，或者分析校對流程點解仍有錯。沿用目前 profile 同 project-local 記錄；唔為少量疑字另建 release 封存流程。

## 分開「點樣變錯」同「幾時發現」

保留人工覆核之前嘅成稿、原始 OCR 回傳同人手答案，唔用套用答案後嘅稿評估原先準確度。對每個改動記 scan、來源圖身份、精確出現位置、各階段讀法同證據路徑；可以用現有表格／JSON，毋須固定新 schema。

追查讀法時按資料實際存在嘅階段比較：原始引擎 → 可取得嘅 writer／修訂稿 → 交付稿 → 人工定案。第二引擎有讀法就另列；冇保存、截斷、該段漏讀、同字多次而無法唯一對齊，都要分開記錄，唔當空字串或相同錯誤。

兩條軸分開計數，唔混成單一「漏錯率」：

| 軸 | 可記錄嘅關係 |
|---|---|
| 讀法變化 | 底稿同人工一致而成稿唔同；底稿與成稿同樣唔同於人工；底稿同成稿係兩種不同錯讀；底稿缺失／該段漏讀／對齊不確定 |
| 發現及交接 | 該字位交付前已存疑並傳遞；只標到同一句或同名其他位置；後來抽查先發現；歷史證據不足 |

字串關係唔等於生成因果。另核底稿產生時間、writer 封稿時間同實際可得嘅讀取／修訂記錄；底稿較早存在亦唔證明 writer 曾採用。冇中間稿時只描述可見 endpoints，唔虛構某輪改字。

已列疑並交人確認嘅字，唔同完全未發現嘅錯。反過來，同一句曾有一個字存疑，亦唔能夠將後來嗰句所有改字都算成已發現。

## 疑點交接要對到同一個位置

- 每項保留穩定 ID、scan、目前候選、短上下文，同足以分辨第幾次出現嘅文字 locator。位置必須對返其依據版本；文字改動後舊 offset 唔自動沿用。
- 交畀人睇圖時，附已目視核實嘅框／crop 同來源圖尺寸、座標約定、render 身份；無可靠框就用清楚欄位描述同整頁定位，唔放估算框令用戶猜。重複姓名每個出現位置分開定位；可分組顯示，唔共用一個未核實框。
- 原圖放大、目前候選同修改範圍要一一對應。提供候選選項時亦容許其他讀法、看不清同原稿正確，唔迫用戶喺兩個錯字之間揀。
- 更正錯框或錯位後，舊答案保留歷史，但受影響題目要重新核對；未完成重核之前唔納入已確認結果。
- 將 actionable fixes、仍待裁定字形、已確認來源異常分開。逐頁覆核完成、程式檢查通過、或者候選「似乎印成噉」唔會自動清除字形存疑；有針對該字位嘅圖像依據或明確人手定案先更新 disposition。
- 人工答案按 exact occurrence 套用，保留異體字。若原圖殘缺，記清係人手定案，唔將之改稱模型獨立清晰讀到。修改後跟目前 profile 做必要嘅重建及 delta review。

## 同名查疑同改善範圍

按 `common-ocr-traps.md` 搜尋同形／近形名稱時，留低查過嘅來源範圍、query／候選生成方式，同每個命中嘅處理。先有現成 ledger 就補嗰份；少量命中可直接列喺報告。確認相同、來源真異寫、仍未定分開記，唔將「搜尋過」當全部位置已裁定，亦唔將冇交人覆核嘅位置當成錯字。

人工確認唔改嘅項目亦要留低，作防止過度更正嘅對照。重複同名改動可以逐處計數，但唔當成多份獨立材料或多種已泛化失效。

根據回溯結果優先修正資料交接、定位同覆核次序。個別字形、人名、套語同書內疑點只入 project 記錄；核心變更仍按 `SKILL.md` 泛化門檻，唔新增固定字詞替換表。跨材料效果未驗證前，只可以報流程已修改，唔聲稱準確率提升。

## 評估口徑

分開報修訂處數、字元替換／刪除／插入數，同圖片處理指示。只挑疑字嘅結果只反映呢批疑字；唔外推全書 CER。展示過 OCR 候選嘅人手答案係輔助覆核，唔叫盲測標準稿。用戶只想做短題就尊重其範圍，唔為計 CER 自動恢復已擱置嘅整頁工作。
